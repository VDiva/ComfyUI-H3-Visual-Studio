# 本地性能优化说明

更新日期：2026-11-11。

本目录中的代码基于原项目 [AIMixer/ComfyUI_MiniMaxH3_Director](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director) 修改。以下记录说明本地优化范围，不代表上游已合并、发布或验证这些修改。

## 修改目标

降低长视频合并、分段导出与缓存恢复时的额外内存占用，减少不必要的数据转换和复制。保留现有工作流接口，不通过减少帧数、降低采样精度或改变编码质量参数来节省资源。

## 已实现的修改

| 位置 | 修改 |
| --- | --- |
| `lib/video_export.py` | MP4 导出逐帧转换 RGB 并写入 FFmpeg，去掉整段 RGB 和整段 `tobytes()` 副本；诊断输出写入临时文件，异常时清理编码进程 |
| `director/segment_mp4_export.py` | 去掉调用编码器之前对整段帧进行 CPU / float 转换，交由编码器逐帧处理 |
| `lib/image_prep.py` | 不同尺寸片段合并时直接写入最终画布，避免先保留全部补边片段再拼接 |
| `director/segment_continuity.py` | 同尺寸、同类型、同设备片段逐段完成接缝计算并写入最终结果；混合布局保留兼容路径；无需修正尾帧时避免提前复制 |
| `lib/frames_ffv1.py` | FFV1 解码分块读取到可写缓冲区，NumPy / PyTorch 共享该缓冲区，减少完整帧数据复制 |

原始采样、接缝计算参数和 H.264 编码质量设置未调整。上述修改旨在保持原有输出行为，实际一致性仍需运行验证。

## 内存与速度限制

“全部导出”仍需构建完整的 IMAGE 张量，原始分段、精修版本与模型也可能同时驻留。优化减少的是中间副本，不能消除最终帧张量本身的占用。

float32 RGB 帧的理论大小为：`帧数 × 高 × 宽 × 3 × 4 字节`。例如 1920×1080、24 fps、60 秒的视频，单份帧张量约为 33.4 GiB，尚未计入模型、音频、编码缓冲和其他版本。

长视频可优先使用已有的“分段导出”，减少完整时间线合并压力。分段模式的输出与全部导出不同，接入下游节点前应确认其需要分段文件还是完整 IMAGE 张量。

实际提速取决于视频尺寸、片段数、磁盘和 CPU/GPU 性能。目前没有量化性能基准，不承诺固定提速比例或完全消除崩溃。

## 验证状态

相关修改已通过 Python 语法解析检查。当前可用 Python 缺少 PyTorch 和 NumPy，以下运行测试被跳过，尚未完成 ComfyUI 工作流实测：

- `tests/test_merge_memory.py`：使用替代接缝运算检查合并调度顺序和输入保护；不覆盖真实接缝算法的逐像素一致性。
- `tests/test_frames_ffv1.py`：检查 FFV1 无损往返、返回缓冲区生命周期与可写性；需要 PyTorch、NumPy 和 FFmpeg。

在已安装项目依赖的 ComfyUI Python 环境中，从插件根目录运行：

```text
python -m unittest discover -s tests -p "test_merge_memory.py"
python -m unittest discover -s tests -p "test_frames_ffv1.py"
```

建议进一步用相同输入、种子与参数比较修改前后的帧数、尺寸、逐像素结果、音频时长及同步情况，并分别记录生成、缓存、合并和导出的耗时与峰值内存。MP4 编码还需覆盖奇数尺寸、带音频与 FFmpeg 异常退出场景。
