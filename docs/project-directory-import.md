# 标准项目目录导入与公共素材库

在导演台工具栏点击“导入项目目录”，使用浏览器文件夹选择器选择完整项目。目录结构与提示词格式见根目录《标准目录与AI交付规范.md》。浏览器上传所选本地文件，云服务器不需要访问本机路径。

## 公共库与运行

公共库不设数量上限，保存在时间轴 global.assetLibrary 下，按 images / audios / videos 分别管理。工具栏“公共素材库”查看编号并追加文件；旧工作流可确认迁移当前公共与各分组素材。项目库模式隐藏分组独立媒体区，提示词 @ 菜单列出公共库。

运行前仅选择提示词中引用的素材并映射为紧凑模型槽位，单段 9 图 / 3 音频 / 3 视频。原时间轴、公共库编号和原提示词不改写。模型限制不通过提高全局 MAX_REFERENCE_IMAGES 绕过，旧工作流保留原有槽位逻辑。

公共提示词（启用时）的引用也计入单段上限。库内未引用的素材仅保存路径，不解码为模型输入。目录导入上传完整索引库，方便后续修改提示词复用。

## 保留与替换

导入替换当前素材组、公共提示词与公共库，保留输出和采样等参数及画布节点接线。外部 Group 节点接线优先的现有规则仍适用：目录导入使用内部素材组时应断开外部组输入，避免覆盖。全库存在素材时导入使用 r2v，纯文本库使用 t2v；模型不会自动替换。

章节按目录名自然排序；章内按索引编号排序。连续性沿用导演台现有规则，章节边界和不同镜头的“引用上段”须自行核对。浏览器上传失败可能留下一部分已上传素材，但不应用新时间轴。

音频/视频每段仍受模型 3 槽限制。图片库追加并不自动推断人物名称或替换引用编号。目录名和文件名允许中文，不支持包含竖线的 Markdown 表格文件名。公共库通过现有导演包 timeline.json 保存，完整导出依赖原有递归媒体打包路径。

## 验证

单元检查覆盖公共库重编号、顺序去重、缺失素材与超过单段上限等。可运行 `python -m unittest discover -s tests -p "test_shared_assets.py"` 和 `node tests/test_project_import.mjs`。前端测试使用模拟浏览器与上传服务，执行真实帧数帮助函数与目录解析逻辑，不需要 PyTorch。浏览器目录上传和真实 GPU 生成需要在 ComfyUI 中验收；未以本地预检替代 GPU 验证。
